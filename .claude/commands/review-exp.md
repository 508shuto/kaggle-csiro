# Review Experiment Steering & Documentation

実験番号を指定して、ステアリングファイルと実験ドキュメントを一括レビューします。

## 使い方

```
/review-exp exp042
```

## レビュー対象

1. **ステアリングファイル** (`.steering/*-$exp_name-*/`)
   - requirements.md - 目的、変更/追加する機能、制約・前提条件
   - design.md - アプローチ、変更コンポーネント、影響範囲
   - tasklist.md - 完了条件、タスク進捗

2. **実験ドキュメント** (`doc/experiment/$exp_name.md`)
   - 目的、ベース、設定、結果、考察

## 実行内容

`$ARGUMENTS` を実験番号として使用し、以下を実行してください:

### Step 1: ファイル収集

```bash
exp_name="$ARGUMENTS"

# ステアリングディレクトリの検索
steering_dirs=$(ls -d .steering/*-$exp_name-*/ 2>/dev/null)

# 実験ドキュメントの存在確認
exp_doc="doc/experiment/$exp_name.md"
```

### Step 2: ステアリングファイルレビュー

各ステアリングディレクトリ内の3ファイルをレビュー:

#### requirements.md チェックリスト

| 項目 | 重大度 | 確認内容 |
|------|--------|---------|
| 目的セクション | Critical | 「## 目的」が存在し、具体的な目標が記載されている |
| 変更/追加する機能 | Critical | 「## 変更/追加する機能」が存在し、変更内容が列挙されている |
| 制約・前提条件 | Warning | 「## 制約・前提条件」が存在し、依存関係が明記されている |

#### design.md チェックリスト

| 項目 | 重大度 | 確認内容 |
|------|--------|---------|
| アプローチ | Critical | 「## アプローチ」が存在し、実装方針が記載されている |
| 変更コンポーネント | Critical | 「## 変更コンポーネント」が存在し、ファイルパスが特定されている |
| 影響範囲 | Warning | 「## 影響範囲」が存在し、副作用が評価されている |
| requirements整合性 | Critical | requirements.md の機能とアプローチが対応している |

#### tasklist.md チェックリスト

| 項目 | 重大度 | 確認内容 |
|------|--------|---------|
| 完了条件 | Critical | 「## 完了条件」が存在し、検証可能な条件が記載されている |
| タスク記載 | Critical | タスクがステータス付きで記載されている（TODO/In Progress/Done） |
| 進捗整合性 | Warning | チェックボックス [x] の数とステータスが一致している |
| design整合性 | Warning | design.md の変更コンポーネントに対応するタスクが存在する |

### Step 3: 実験ドキュメントレビュー

#### doc/experiment/$exp_name.md チェックリスト

| 項目 | 重大度 | 確認内容 |
|------|--------|---------|
| 目的 | Critical | 「## 目的」が存在し、requirements.md と整合している |
| ベース | Warning | 「## ベース」が存在し、ベース実験が明記されている |
| 設定 | Warning | 「## 設定」が存在し、主要パラメータが記載されている |
| 結果 | Warning | 「## 結果」が存在し、CV/LBスコアの記載欄がある |
| 考察 | Info | 「## 考察」が存在する |

### Step 4: クロスバリデーション

| チェック項目 | 重大度 |
|-------------|--------|
| requirements.md の目的 ↔ 実験ドキュメントの目的が一致 | Critical |
| design.md の変更コンポーネント ↔ 実験ドキュメントの設定が整合 | Warning |
| tasklist.md の完了状況 ↔ 実験の進行状況が整合 | Warning |

### Step 5: レポート保存

レビュー結果を以下の形式で保存:

**保存先**: `.log/review/YYYYMMDD-$exp_name-steering-review.md`

## 重大度の定義

| 重大度 | 基準 | 例 |
|--------|------|-----|
| Critical | ドキュメント間の矛盾、必須セクション欠落 | 目的の不一致、完了条件なし |
| Warning | 情報不足、曖昧な記載 | 影響範囲の記載なし、考察が空 |
| Info | 記載の改善提案 | より具体的な記述の推奨 |

## エラーハンドリング

### ステアリングディレクトリが存在しない場合

```
Warning: 実験 $exp_name に対応するステアリングディレクトリが見つかりません。
検索パターン: .steering/*-$exp_name-*/

対応:
- ステアリングを作成する場合: mkdir -p .steering/YYYYMMDD-$exp_name-[タイトル] を実行
- ステアリングなしで進める場合: 実験ドキュメントのみをレビュー
```

### 実験ドキュメントが存在しない場合

```
Warning: 実験ドキュメント doc/experiment/$exp_name.md が存在しません。

対応:
- CV完了後に作成してください（テンプレートはCLAUDE.mdを参照）
- 学習前の段階であれば、後で作成予定として記録
```

### 両方とも存在しない場合

```
Error: 実験 $exp_name に関連するファイルが見つかりません。

確認事項:
1. 実験番号が正しいか確認してください（例: exp042）
2. 利用可能な実験: ls doc/experiment/ で確認
3. 利用可能なステアリング: ls .steering/ | grep $exp_name で確認
```

## 関連コマンド

- `/stage-exp <expXXX>`: 実験ファイルをgit addでステージング
- `code-reviewer`: 実験コードのレビュー（バグ、パフォーマンスなど）
